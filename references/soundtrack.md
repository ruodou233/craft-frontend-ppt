# 配乐设计

创作型 Build 和大幅 Improve 默认使用本参考；其他任务在新增、替换或调整音乐层时使用。

## 从源内容建立配乐方向

先读完源内容，按主张、情绪、能量或节奏发生实质变化的位置划分段落。为每段建立 cue sheet，记录：

- 对应的源内容、场景和时长；
- 情绪、能量、速度、节奏密度、音色和声音材料；
- 应该何时进入、保持、降低存在感或结束；
- 与此段视觉事件和演讲内容的对应关系。

为了让配乐跟随讲稿而不被固定模板支配，使用同一套声音母体保持完整作品的连续性，并按实际情绪段落决定 BGM 的数量、边界与切换方式。内容情绪有明显变化时使用能体现差异的音乐段落，不用一首音乐无区分地覆盖全程。

## 制作音乐

默认使用纯音乐，不含歌词、人声对白或会与讲述竞争的人声采样。为每个 cue 撰写可直接使用的生成提示词，写明用途、情绪弧线、速度、配器、质感、讲述留白、时长和需要排除的元素。

为了避免把合成声音或提示词冒充配乐，创作型作品的主音乐层必须是经过完整试听、保存到本地项目并已实际集成的无歌词音乐文件；Web Audio 振荡器、随机音符、提示音、环境底噪、程序化 drone 或 UI 声效默认只算声音设计或技术后备。只有用户明确要求生成式声景，且最终视觉导演完整实听并确认它承担了配乐职责时，才可作为例外。优先使用项目已获准的音频；需要新制作时，使用已获授权的音乐生成服务或其他可追溯来源。实际音频因缺少授权、登录态、工具或试听条件而无法制作时，明确报告交付尚未完成，不把 cue sheet、提示词、占位声或程序合成声当作音乐成品。

为了让指定的生成来源和最终文件可追溯，用户指定 Suno，或任务上下文已授权使用 Suno，且环境具备已登录浏览器时，安排独立音乐制作子代理按 cue sheet 生成候选、逐一完整试听、选择并下载音频。提示词明确写入 `instrumental only`，并排除歌词、对白、哼唱、合唱和会与讲述竞争的人声；记录生成提示词、来源服务、版本、使用权限、试听结果、采用与淘汰决定，再把采用版本保存到项目的 `assets/audio/` 或等价本地目录并实际集成，不依赖生成页面、临时 URL 或远程流媒体。

## 集成到作品

- 把采用的音频保存到项目目录，使用稳定相对路径，并记录每个文件对应的 cue；在断网、清空缓存和直接打开生产交付包的条件下确认仍可播放。
- 将 cue 与场景或段落建立确定性映射，保留演讲或展示时的手动选择能力。
- 为网页音频提供明确的启用、播放、暂停、恢复、静音、音量和加载失败状态；遵守浏览器的用户手势启动限制。
- 让音乐在讲述下保持足够的音量和频段空间，把现场扩声或实际播放设备试听作为制作阶段的一部分。
- 仅预载开场必需元数据或音频；后续 cue 按场景与网络条件加载，并提供可用的失败后备。

## 在制作阶段验证

为了让“有音频文件”和“音乐完成”可以被区分，指定审听者必须从头到尾完整试听每个最终采用的 cue，并记录文件名、时长、试听日期、审听者、是否含歌词／对白／哼唱／合唱／抢占讲述的人声、明显故障、与情绪段落的适配及采用或淘汰决定。集成后逐一实际加载和播放，确认文件有效、场景映射正确，且用户手势启动、启用、暂停、恢复、静音、音量和失败处理可用；按场景前进和倒退时检查确定性映射。在代表性宽屏和窄屏上检查音频控件不遮挡内容。把环境无法完成的试听、扩声、离线或设备验证标为未验证，不以代码存在、元数据或波形检查代替实际试听。
